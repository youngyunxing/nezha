# 任务状态机

这份文档回答两件事：**每个状态是什么意思、什么时候进入**，以及**看到它你该干什么**。
判断状态只依据四类事实，不依据"上一步点了什么"：

1. 进程活没活（PTY 子进程）
2. 大模型在不在干活（hook：`UserPromptSubmit` / `PostToolUse` 置 `running`，`Stop` 收尾）
3. 有没有东西卡在等你（权限请求 / 提问）
4. 结束得好不好

## 状态表

| 状态 | 什么情况 | 何时进入 | 何时离开 | 列表文案 | 你要做什么 |
|---|---|---|---|---|---|
| `pending` | 正在拉起进程 | 新建 / 恢复时先置 | spawn 成功 → `idle` | 启动中 | 等 1–2 秒 |
| `idle` | 会话就绪，**没人在干活** | spawn 完成（run / resume / fork）；「已读」后回落 | 你提交 → `running`；卡住 → `input_required` | 空闲待命（agent）<br>终端就绪（纯终端） | 派活 / 直接用 |
| `running` | **大模型正在生成 / 跑工具** | hook `UserPromptSubmit`、`PostToolUse` | `Stop` → `awaiting_review`；卡住 → `input_required` | 正在处理 | 等它说完 |
| `input_required` | 被权限请求 / 提问**卡住** | hook `PermissionRequest`、`Notification`；末尾是问句的 assistant（启发式） | 你回答后继续跑 → `running` | 等你确认 | 必须去回它 |
| `awaiting_review` | 这轮答完了，**内容你还没看** | hook `Stop` | 你提交下一句 → `running`；**看过 → `idle`** | 有新回复 | 去看、去回、或先放着 |
| `interrupted` | 上次没退干净，**进程已死但会话可续** | 启动归一化（活动态 + 无子进程）；退出应用时 | 恢复 → `idle` | 中断待恢复 | 点恢复 |
| `interrupted` + `processAlive` | **进程还活着**，但这个 app 没接上（上次强退） | 启动归一化（活动态 + 有子进程） | 重连 → `idle` | 连接断开 | 点重连 |
| `done` | **正常结束**，记录都在、可续跑 | 进程退出，且退出时没在干活、也产生过会话 | 恢复 → `idle` | 已完成 | 想继续就恢复 |
| `failed` | **压根没跑起来，或干活时崩了** | 进程退出，且（从未产生会话 **或** 退出时状态是 `running`） | 重试 → `pending` | 失败 | 看原因再重试 |
| `cancelled` | **你取消的**（删项目、退出应用时取消在跑的任务） | `cancel_task` | — | 已取消 | 无需处理 |

## 触发时机（信号 → 状态）

| 信号 | 谁发 | 结果 |
|---|---|---|
| 新建 / 恢复任务 | 前端 | `pending` |
| 进程 spawn 成功 | 后端 | `idle` |
| `SessionStart`（含重启恢复后的启动） | hook | **不改状态** —— 恢复后闲置的会话因此停在「空闲待命」 |
| `UserPromptSubmit` | hook | `running` |
| `PostToolUse` | hook | `running` |
| `PermissionRequest` / `Notification` | hook | `input_required` |
| `Stop` | hook | `awaiting_review` |
| 你看了这个任务（它正显示在前台、窗口有焦点） | 前端 | `awaiting_review` → `idle` |
| 进程退出 | 后端 | `done` / `failed`，判据见下 |
| app 启动：活动态 + 无子进程 | 前端归一化 | `interrupted`（`processAlive = false`） |
| app 启动：活动态 + 有子进程 | 前端归一化 | `interrupted`（`processAlive = true`） |
| app 退出 | 前端 | 活动态 → `interrupted` |
| 取消（删项目 / 退出时） | 后端 | `cancelled` |

## 两条有实测依据的判据

**退出时算完成还是失败**：`claude` 用 `/exit` 正常退出时**退出码是 1**（实测），
所以「非 0 就是失败」会把每次正常关闭都标红。改用两个真实信号：

- 从未产生过会话 → `failed`（CLI 起不来、`--resume` 失败这种，例如会话文件不存在）；
- 退出时状态是 `running`（后端记录的最近一次 hook 状态）→ `failed`（干活途中崩了）；
- 其余 → `done`。

**恢复后为什么是「空闲待命」而不是「正在处理」**：状态只由 hook 驱动，`SessionStart`
不改状态，所以进程起来、会话就绪、但没人干活时就是 `idle`。真正提交提示词后
`UserPromptSubmit` 才会把它切成 `running`。

## 列表分组（顺序即优先级）

| 分组 | 收哪些状态 | 含义 |
|---|---|---|
| 等你 | `input_required`、`awaiting_review` | 轮到你了：一个必须回（卡住），一个可以慢慢看（有新回复） |
| 待恢复 | `interrupted` | 进程断了，需要你点一下（重连 / 恢复） |
| 待合入 | `done` + 有工作树 | 干完了，等你决定合不合 |
| 星标 / 今天 / 更早 | 其余 | 按修改时间归档 |

`running` / `idle` / `pending` 不进「等你」——它们不需要你做任何事。项目栏头像上的
小圆点 + 招手动画只跟「等你」两种状态有关。

## 流转图

```
新建/恢复 ─► pending ──spawn ok──► idle ◄──────── 恢复 / 重连 / 已读回落
                                    │  ▲
                        你提交提示词 │  │ Stop（看完就回落）
                                    ▼  │
                                running ────► awaiting_review（有新回复）
                                    │  ▲             │
                    被权限/提问卡住  │  │ 你回答       │
                                    ▼  │             │
                              input_required         │
                                    └── 进程退出 ─────┴──► done / failed

中断（进程没了）→ interrupted ──恢复──► idle
中断（进程还在）→ interrupted ──重连──► idle
```
